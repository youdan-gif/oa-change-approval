1创建 CloudBase 环境

CloudBase 环境是所有云服务的容器，需要先创建环境才能部署服务。

操作步骤

  1. 打开浏览器，访问：https://tcb.cloud.tencent.com/dev
  2. 使用您的腾讯云账号登录（如果没有，点击注册，手机号即可注册）
  3. 登录后，点击页面上的 "新建环境" 按钮
  4. 填写环境信息：
    • 环境名称：输入 oa-system（随便起名，自己记住即可）
    • 地域：选择 上海（必须选上海，云托管仅支持上海）
    • 套餐：选择 个人版（有免费额度）
  5. 点击"开通"，等待约1-2分钟创建完成
  6. 创建完成后，你会看到环境ID，类似 oa-system-xxxxx，记下来
说明
个人版套餐包含一定的免费额度，对于小型OA系统（几十人使用）完全够用。

2创建云托管服务（Git 部署）

代码已经推送到 GitHub，接下来在 CloudBase 中连接 GitHub 仓库自动部署。

操作步骤

  1. 进入刚才创建的环境后，在左侧菜单找到 "云托管"，点击进入
  2. 点击 "新建服务"
  3. 服务信息填写：
    • 服务名称：oa-system
    • 部署方式：选择 Git 部署
  4. GitHub 授权：
    • 点击"授权 GitHub"，会跳转到 GitHub 登录页面
    • 登录 GitHub 账号（之前注册的 349678981@qq.com）
    • 授权 CloudBase 访问你的仓库
  5. 选择仓库：
    • 选择仓库 youdan-gif/oa-change-approval
    • 分支选择 main
  6. 构建配置：
    • 容器端口：输入 3000
    • 环境变量：点击"新增"，填写：
      • 变量名：NODE_ENV，值：production
      • 变量名：DATA_DIR，值：/app/data
  7. 其他选项保持默认，点击 "确定"
  8. 等待构建完成（约3-5分钟），状态变为"运行中"即表示成功
注意
构建过程中会下载依赖和编译 native 模块，可能需要 3-5 分钟。如果构建失败，请查看构建日志中的错误信息。

3配置持久化存储（关键步骤！）

为什么需要这一步？
云托管的容器实例默认使用临时存储，实例重启或重新部署后数据会丢失。对于OA审批系统，数据丢失是不可接受的！
通过挂载 CFS 文件存储，可以确保数据库永久保存。

3.1 创建私有网络（VPC）

  1. 打开新标签页，访问：https://console.cloud.tencent.com/vpc
  2. 确认地域选择为 上海（页面顶部）
  3. 点击"新建"，填写：
    • 名称：oa-vpc
    • 可用区：选择"上海二区"或任意
    • 子网名称：oa-subnet
    • IPv4网段：保持默认 10.0.0.0/16
  4. 点击"确定"创建完成

3.2 创建 CFS 文件存储

  1. 访问：https://console.cloud.tencent.com/cfs
  2. 确认地域为 上海
  3. 点击"新建文件系统"，填写：
    • 名称：oa-cfs
    • 文件协议：NFS（默认）
    • 存储类型：通用型标准（性价比最高）
    • 网络/私有网络：选择刚才创建的 oa-vpc 和 oa-subnet
  4. 点击"确定"，等待创建完成（约1-2分钟）
  5. 创建完成后，记录文件系统ID（类似 cfs-xxxxx）

3.3 在云托管中启用 VPC 和 CFS

  1. 回到 CloudBase 控制台，进入"云托管" → 点击你的 oa-system 服务
  2. 找到 "服务设置" 标签页
  3. 启用私有网络：
    • 找到"私有网络"部分，点击"启用"
    • VPC 选择：oa-vpc
    • 子网选择：oa-subnet
    • 点击保存
  4. 启用存储挂载（CFS）：
    • 找到"存储挂载"部分，点击"启用存储挂载"
    • 存储类型：选择 文件存储 CFS
    • 文件系统：选择 oa-cfs
    • 挂载点：选择可用的挂载点
    • 远程目录：/（默认）
    • 实例挂载路径：输入 /app/data（重要！必须和 DATA_DIR 环境变量一致）
    • 权限：读写
    • 点击保存
  5. 保存后，重新部署服务（在服务页面点击"重新部署"），使存储挂载生效
完成！
设置完成后，你的 SQLite 数据库将存储在 CFS 持久化存储中，即使实例重启或重新部署，数据也不会丢失。

常见问题

Q: 构建失败怎么办？

查看构建日志。常见原因：网络超时导致 npm install 失败，可以尝试重新部署。如果是 better-sqlite3 编译失败，确认 Dockerfile 使用了 node:18-slim 镜像。

Q: 访问地址打不开？

等待服务完全启动（约30秒-1分钟）。如果长时间打不开，检查服务状态是否为"运行中"，查看日志是否有启动错误。

Q: 不配置 CFS 会怎样？

数据会在实例重启或重新部署后丢失！如果不配置 CFS，系统仍然可以运行，但所有审批数据、用户注册数据都存在丢失风险。强烈建议完成第3步。

Q: CFS 收费吗？

CFS 文件存储按实际使用量计费，通用型标准存储约 0.0002元/GB/小时，对于小型OA系统（数据库通常不到 100MB），每月费用约 1-2 元，几乎可以忽略不计。

Q: 如何后续更新代码？

代码推送到 GitHub 的 main 分支后，CloudBase 会自动重新构建部署。如果设置了 CFS，数据库数据不会受影响。

Q: 忘记管理员密码怎么办？

在 CloudBase 控制台进入服务日志，查看启动日志中有默认账号信息。也可以通过重置数据库（删除 CFS 中的数据文件）来恢复默认账号。
